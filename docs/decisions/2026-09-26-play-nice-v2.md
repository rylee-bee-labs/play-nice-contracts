# Decision: Play-Nice v2 — simpler, friendlier, and actually used

Date: 2026-09-26. Approved by the repository owner ("Yes, go").

## In short

Play-Nice becomes one short **floor** page everyone reads, plus **7 packs**
(about 34 contracts, down from 67) in one plain shape. One installable-free
tool, `playnice`, sets a project up and checks it. Proof of being current is
one line for agents, a small public file for sites, and a **bee badge** for
projects. Then the owner's own repos adopt it for real.

## Why

Evidence: [contracts map](../background/research/2026-09-26-contracts-map.md) and
[tools usability test](../background/research/2026-09-26-tools-usability.md), both
2026-09-26, plus a direct read of the README, index and tools.

- Only three of the owner's repos adopt it (Worlds, homelab, VEFR, under
  `.project/contracts/`), and in practice work runs on each repo's
  AGENTS.md. (Corrected 2026-09-26: an earlier draft said none.)
- 67 contracts, ~47,000 words; a worker's onboarding lists 22 contracts.
- Resolving a task ("build a web page with a form") returns the same 8
  general contracts as any task; UI, accessibility and wording never appear.
- The gate is eight steps (freshness, resolve, read, verify hash and
  receipt, acknowledge, attest, commit) and proves reading, not following.
- First use: no installed command, three ways to call it, `onboard --role
  agent` refused, `init-project` writes a manifest its own tools crash on,
  `status` reports PASS in a folder that has not adopted anything.
- Overlaps (attention / interruption / quiet-when-healthy / progress; parity /
  machine-readable output; four "cooperate nicely" contracts) and no contract
  for websites being friendly to agents.

## What changes

1. **Floor.** One page, about 15 plain rules, that fits in any context. Every
   participant (human, agent, tool, site) reads it; agent configs load it by
   default. It carries one receipt word per version.
2. **Packs** (grouping by what you are building):

   | Pack | For |
   |---|---|
   | Everyone | truth and UNKNOWN, status words, asking for help, working together, recovery, ownership |
   | Agents and work | bounded work, handoffs, testing and evidence, git |
   | People | attention, accessibility, motion and sensory safety, depth on demand, themes |
   | Surfaces | API, CLI, web UI, rooms, plain words, one truth for people and machines, every setup checks itself (new) |
   | Sites | new: a website that is friendly to agents and people |
   | Integration | capabilities not vendors, calling other services, webhooks and caching, versioning |
   | Access | identity and roles, secrets and data classes, public and private boundaries |

3. **One shape** for every contract: *In short* (3 lines), *Applies when*,
   *Rules* (numbered; MUST / SHOULD kept), *Examples*, *Why* (short),
   *You're done when* (checkable), optional *Machine notes*. Target ≤ 800
   words and ≤ 15 rules each. Tool mechanics move to tool docs.
4. **One tool: `playnice`** (contractctl and playnice merged; old names stay
   as aliases for a release). No install: `uvx playnice …`; one-line GitHub
   Action. Commands: `start` (asks what you are building, writes the optional
   adoption file), `check` (works out what the repo is, runs checkable rules,
   writes the badge), `verify "<receipt line>"`, `show`, `upgrade`. Every error
   says what went wrong and the next step.
5. **Proof, lighter.**
   - Projects: the **honeycomb bee badge** (owner's pick), states *plays nice
     · vX*, *behind · vY is out*, *fix needed*; state in words, not colour
     only. Redrawn by the project's own CI; the badge links to the check run.
   - Agents: one line, `Play-Nice floor <version> · receipt <word>` (plus packs in
     use); `playnice verify` answers current or out of date.
   - Sites: `/.well-known/play-nice.json` (version, packs, contact);
     `playnice check https://site` runs light checks and gives the same badge.
   The eight-step gate and attest/commit ritual are retired.
6. **Design philosophy page** (not a design system): plain, warm, short voice;
   rule first, reason second; stories only on a separate "why" page; one
   badge style with a bee mark; accessible in plain text, screen readers and
   small screens.
7. **The home of the owner's frameworks.** The agent constitution, the
   plain-language rule, "every setup checks itself", roles and permissions,
   and ROOM live here; agent-config generates each repo's AGENTS.md from the
   floor; Worlds, Project Home, Candy and homelab adopt with one CI check.

## Borrowed from

| Source | What we take |
|---|---|
| [REUSE](https://reuse.software/dev/) (FSFE) | Short spec + one lint tool + a [live badge](https://api.reuse.software/): the model for `playnice check` and the bee badge; later an optional check service. |
| [AGENTS.md](https://agents.md/) | Don't invent an agent file: `playnice start` writes the floor's rules into the repo's AGENTS.md (short block + link). |
| [llms.txt](https://llmstxt.org/) | Sites pack recommends it; Play-Nice publishes its own. |
| [A2A agent card](https://a2a-protocol.org/latest/topics/agent-discovery/) | `/.well-known/play-nice.json` follows RFC 8615; agent sites link their agent card. |
| security.txt (RFC 9116) | `contact` and `expires` fields, so a site's claim goes stale on its own. |
| RFC 9457 problem details | API errors in the Surfaces pack. |
| OpenSSF Scorecard | Each check says why it matters and how to fix it. |
| Diátaxis | Docs split: tutorial (start here), how-to, reference (floor, contracts), explanation (why pages). |
| Vale | `check --docs` flags jargon, so the plain-language rule is enforced by a check. |
| pre-commit | A hook as the other zero-friction way to run `check`. |

Evidence on agent context files: ["Evaluating AGENTS.md"](https://arxiv.org/abs/2602.11988)
found repository context files did not raise task success on average and
added over 20% inference cost; instructions in them were followed reliably,
while repository overviews did not help. So the floor stays short and
imperative, and only its **Rules** list (no examples or why) goes into a
repo's AGENTS.md.

## Reversibility

Every step is a normal PR. Old contract ids stay as aliases, old command names
stay as aliases for one release, and the v0.10.0 library stays pinned for any
consumer until it upgrades.
