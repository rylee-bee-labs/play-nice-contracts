## [Unreleased]

### Added
- Install with uv or pipx:
  `uv tool install git+https://github.com/rylee-bee-labs/play-nice-contracts`
  gives a `playnice` command. The package holds only a small launcher
  (`tools/playnice/playnice_launcher.py`, standard library only, no
  dependencies) that runs `playnice.py` from a library checkout:
  `PLAY_NICE_LIBRARY`, the checkout you are in, or a managed clone in
  `~/.cache/play-nice/contracts` that is fast-forwarded at most once a day.
  The rules are never copied into the install. CI builds and runs the
  package on every push.

### Changed
- A by-hand run of the release workflow for a version that is already
  released refreshes that release's notes from `CHANGELOG.md`, so a
  corrected changelog reaches the release page without editing it by hand.
  The 2.1.0 notes are corrected this way: they said v2.0.0 was tagged on
  `a9c4197`; it is on `c7b1f71`.

### Fixed
- Tests: the shared Git baseline repo turns off automatic maintenance before
  its commit. On CI a background `git maintenance run` sometimes removed
  lock and temp-pack files while a test was copying the repo
  (`shutil.Error: No such file or directory`).

## [2.1.0] - 2026-10-27

Tidy and self-running: contract changes are enforced after commit and bumped with one command, releases and generated files take care of themselves, the history sits in one place, and the tests run faster. Plan: `docs/decisions/2026-10-26-play-nice-neat.md`.

Release tags start here: this release, and `v2.0.0`, published after the
fact on 2026-10-27 at `c7b1f71`, the commit where 2.0.0 landed.

### Added
- `contractctl release X.Y.Z` prepares a library release in the working
  tree (moves the `[Unreleased]` entries under `[X.Y.Z] - <date>`, writes
  `VERSION` and the README version mentions) and `contractctl release-notes
  X.Y.Z` prints that section. `.github/workflows/release.yml` tags `vX.Y.Z`
  and publishes those notes when a `VERSION` change reaches `main`.
- `tools/check-generated.sh` checks every generated file (lock, index
  columns, badge, AGENTS block) without editing any, naming the regenerate
  command for each stale one. `./tools/check.sh` and CI run it in place of
  the old lock-only step.
- `.github/workflows/health.yml`: `./tools/check.sh` on `main` every Monday;
  one `health-check` issue on failure, closed when healthy again, silent
  otherwise.
- Decision record `docs/decisions/2026-10-26-play-nice-neat.md` (Proposed):
  the owner's chosen shape for 2.1.0 (tidy, self-running), 2.2.0 (pack
  cards, generated site, uv/pipx install) and 3.0.0 (one `playnice`
  command, legacy gate removed).
- A SessionStart hook (`.claude/hooks/session-start.sh`) installs pytest,
  pytest-xdist and pyyaml in Claude Code cloud sessions, so `./tools/check.sh`
  runs at once. It does nothing outside cloud sessions or when they are
  already installed.
- `contractctl bump <id> --patch|--minor|--major [--note "..."]`: run it
  after editing a contract. It sets the version, rotates the receipt for
  MINOR/MAJOR (to a word the library has never used, checked against Git
  history), adds the `[Unreleased]` changelog bullet, updates the index row
  and regenerates the lock. Running it again changes nothing. Old v1 ids work.
- `contractctl validate --base <rev>` (or `PLAY_NICE_BASE`). Errors from
  `validate`, `lock` and `index` now end with `next:` lines naming the
  command that fixes them.
- `tests/test_doc_facts.py`: README and AGENTS.md versions, floor proof-line
  examples and rule counts must match their sources.
- The **handoff-and-continuity** 2.1.0 contract now carries explicit owner-approved direction across agents, conversations, Project Home and GitHub without redundant design re-approval. It preserves separate authenticated action gates, implementation proof and deliberate holds. Receipt rotated and contract lock updated.
- `playnice work` reads the repo's own definition of done: the `## Verify`
  section of its AGENTS.md. The commands in that section's code blocks go
  into the work permit (`verify`, `worker_packet.VERIFY`), the work output
  (`VERIFY: DECLARED (n command(s) from AGENTS.md)`) and the worker prompt,
  which tells the agent to run them and show their output in VERIFIED. A repo
  without the section gets `VERIFY: UNKNOWN (<what is missing>)` and the
  agent is asked to propose one; work is not blocked.
- `playnice start --no-workflow` sets a repo up without writing
  `.github/workflows/playnice.yml`, for a repo with its own CI; the README
  badge then links to the library. The floor-change recipe in
  `docs/MAINTAINING.md` uses it instead of deleting the file afterwards.
- `contractctl resolve --json` (`play-nice/resolve-v1`): every selected
  contract with each reason it was selected (`source`, `trigger`, and `via`
  task text or explicit tag), for orchestrators. `resolve_set()` also
  returns this as `reasons`; `selected` keeps its old shape.
- `plain-language` 2.1.0: important unfamiliar concepts get a concrete everyday way in; structural analogies are encouraged when they clarify useful relationships, but may never replace or contradict the literal explanation. Receipt rotated.
- `depth-on-demand` 2.1.0: simplified explanations and analogies are scaffolding, not dead ends; the real term and mechanism stay reachable, and consequential limits of an analogy are exposed before a learner would rely on the wrong model. Receipt rotated.
- `docs/principles/scotty-principle.md`: non-normative learner-facing philosophy for structural analogies — "understand the system deeply enough to explain it simply without making it wrong." It defines the five-year-old test as a prerequisite-load test, not baby talk, and keeps analogy out of machine semantics.
- `status-and-state` 2.1.0: `failed` joins the shared status words, meaning
  a finished operation that did not succeed (the reason goes in a field, not
  a new word). The list is noted as two kinds of word, health and progress.
  One test (`tests/test_status_words.py`) keeps the lists in the floor, the
  quick reference and this contract equal to the schema enum.
- `git-and-worktrees` 2.1.0: size a pull request to one feature or fix, not
  one edit. Bundle a fix, its test and its docs into one PR and add
  follow-ups to the open PR, because every PR runs every check twice and
  often builds an image. Update a branch from main only when needed to merge.
- `library` 1.2.0: one book per idea (glossary `book: "keeper:id"`, shelves
  hold other keepers' books by `ref`, never copies) and teach while building
  (glossary `teach` and `when`; the first / again / familiar stages; one mode
  per person; a glow, never a popup; silence over a wrong lesson). From
  Book Girl, live in VEFR (Fróði) and Worlds' learning memory.
- `library` 1.1.0: tap to learn (from VEFR). A library may carry one shared
  `glossary` (term -> `plain`, the keeper's own `local` name, `also`
  spellings); an *italic* word matching a term is tappable and shows a small
  card on demand. Keepers check that every italic term has an entry.
- `library` 1.0.0 (new, surfaces pack): shelves of layered books (plain
  `short`, plain pages, the keeper's `voice`, `words` to know, `technical`
  under the hood), one keeper per library, and a home that gathers them
  side by side without merging. `look` and `cover` are display hints.
  Served at `GET /room/library`; schema `schema/library.schema.json`.
  First keepers: Worlds, Hive Works; VEFR next.
- `room` 2.2.0: a room may serve optional extras it lists in the
  descriptor's `offers` (`views`, `art`, `library`), and ping its front
  door when its data changes (content-free, only triggers a re-read). A
  need may set `allow_text` to take an answer in the person's own words
  (`{need, text}`). Rule 1 now says "five required endpoints".
- `room` 2.1.0: a need may carry up to six `choices` (optional), so a front
  door can offer a decision as buttons (first user: Hive Works). The
  Machine notes now say `unhealthy`, matching rule 2 and the schema.

  `VERSION` says it (the commit where it landed), and can be run by hand with
  a `version` to publish an earlier one there, not marked latest. This
  session cannot push tags, so v2.0.0 is published this way.
- History trimmed in place so the top level shows the product. The 21
  one-line "Moved to" pointer files left at the old `docs/` paths in the

  `tests/test_doc_links.py` now fails if a pointer file comes back.

- `playnice check` and `playnice status` use the shared status words (floor
  rule 8). Per-check results: `worked` → `healthy`, `needs_fix` →
  `needs_attention`, `skipped` → `not_configured` (`unknown` when the secret
  scan could not run, `unavailable` when `/llms.txt` could not be fetched).

  git unexpanded); `a/b/c` is a path, not `github.com/a/b/c`; a floor
  receipt must be three words, as `contractctl validate` already required.
  contractctl's `_remote_url` is now public as `remote_url`. The two YAML
  parsers stay separate on purpose (config needs integers and quoting that
  manifests must not get); `tests/test_playnice_dedupe.py` pins why.
- `contractctl` has one default contract set, `DEFAULT_CONTRACT_SET`: the
  four everyone basics (truth-and-evidence, status-and-state,
  recovery-and-history, ask-for-help) plus the five agent-work ones
  (agent-behavior, bounded-work, handoff-and-continuity,
  testing-and-evidence, contract-proof). `resolve` without a manifest,
  `init-adoption` and `init-project` all use it; before, each had its own
  list. The `human` and `service` role sets are unchanged.
- `contractctl validate` also checks that each contract's `layer` is its pack
  folder, that it has the In short, Applies when, Rules, Why and You're done
  when sections, that each index row's Title, Purpose and pack section match
  the contract, and that `aliases.json` points only at live contracts, never
  shadows one, and equals the index's "Old names" table. Each error has a
  `next:` hint.
- `contractctl index --write` adds the row for a contract the index is
  missing, in its pack's table at its sorted place (`floor` first, then
  alphabetical). Rows for unknown ids are still reported, never deleted. The
  surfaces table is now in that order (`library` moved).
- `contractctl --help` lists its commands in three groups (everyday,
  adopters, legacy gate) from one table that also registers them. Command
  names and behavior are unchanged.
